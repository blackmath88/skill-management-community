# Companion research — decisions and next experiment

Date: 12 November 2026.
Input: owner-supplied Perplexity report, “Verdict: build the companion experiment—not yet the companion platform”.
Status: owner requested integration after discussion. This is a selected synthesis, not a reproduced report or independent verification of its literature review.

## Adopt for the next prototype

- Preserve the “honest CV for yourself”: real attempts, assistance, conditions, conflicting feedback and uncertainty.
- Make identity options available from day one. A complete appearance is not earned through attendance.
- Keep identity, temporary expression, selected memories and underlying evidence separate.
- Let users curate a small set of memories. Do not automatically accumulate ornaments with every logged activity.
- Allow rearrangement and changing motifs to express personal evolution. Avoid implying that visual richness measures competence.
- Keep a comparably useful character-free history and navigation.
- Start with the geometric Assemblage family and the existing Zdog direction as the implementation hypothesis. Final art direction remains open.
- Begin with a companion beside the user, with minimal agency. Test “represents me” separately.
- Defer XP, shops, cosmetic unlock economies, multiple finished visual worlds and new AI integration in this companion slice. Existing historical progression records are not to be rewritten.

## Strongest objection

Even without a score, a richer character may communicate greater capability. Test what people infer before explaining the symbolism. More documentation is not necessarily more development.

Our response is not to freeze the character. Meaningful visual evolution may come from a changed arrangement, a chosen bridge between parts or a memory recalling help. These are personal interpretations, not automatic capability claims.

## Research status

The supplied report compares portfolios (Mahara/PebblePad), companions (Finch/Voidpet), gameful action (Habitica/SuperBetter), activity visualisation research (Fish’n’Steps/UbiFit) and creature editors. Its useful conclusion is adjacency, not established novelty.

It connects self-regulated learning, reflection, personal informatics, gamification and avatar ownership. The proposed chain—authorship, ownership, revisiting, calibration, better action, transfer—remains unvalidated for this product. Do not turn the report's abstract-level findings, version table or planning estimates into verified facts. Follow original sources in the existing research materials before external efficacy claims.

## Smallest convincing slice

Three core shapes, six identity attachments, four palettes, three memory motifs, one editor, one evidence panel. Counts are scope proposals, not research-derived optima.

Synthetic examples:
1. A linked loop recalls an attempt with a colleague's help.
2. A turned route recalls a partial attempt and changed next move.
3. Paired inlays recall conflicting feedback without averaging it away.

Choose memory → inspect evidence → choose next action must work through labelled HTML controls, independently of the graphic.

Store a versioned semantic assembly and separate catalogue version. Validate one root, allowed connections, unique IDs, no cycles, bounded transforms and import limits. Invalid imports do not replace the current save. Deleting evidence removes its claim; the user may retain the shape as an unlinked decoration.

Default export is appearance only. Journal export is a separate explicit operation. Opaque IDs can still be linkable identifiers: exclude evidence associations from a cosmetic sharing package.

## Sequence and acceptance

1. Visual proof: three compositions from one family, including a complete day-one identity.
2. One vertical interaction: assemble → record synthetic attempt → select memory → revisit.
3. Save/reload, validated export/import, keyboard parity, undo, reduced motion and static fallback.
4. Check rendering stops when settled/hidden; measure actual load and mobile responsiveness.
5. Formative interpretation study proposal, followed only if useful by a longer comparative pilot.

A second engine spike is conditional on a demonstrated visual or interaction limitation. Do not build two engines by default. For Zdog test adapter failure and fallback; GPU context/device-loss handling applies only if adopting a corresponding renderer.

Evaluate ownership, correct understanding of evidence, retrieval, next-action usefulness and burden. Compare equally polished interfaces. Enjoyment alone may justify an optional aesthetic feature but does not demonstrate learning. No recruitment, telemetry or pilot has been authorised or executed.
