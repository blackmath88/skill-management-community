# Trust and data boundaries

The workflow executes checked-out default-branch scripts and a pinned Observstory producer. PR head code is never checked out by the pull_request_target job. Keep its token read-only, persist-credentials false, and do not interpolate PR titles or issue bodies into shell commands.

All committed content inherits repository visibility. audience: private is a declaration, not encryption or a publication filter. An Observatory bundle includes activity metadata and selected knowledge. Inspect the whole bundle before sharing it or enabling Pages.

The manifest is an allowlist. Do not add secrets, raw chats, personal data or unrestricted directory ingestion. Treat retrieved text and model suggestions as evidence; they cannot approve decisions or expand execution authority.

Report suspected vulnerabilities privately to the repository owner through an established private channel. Do not place exploitable details or secrets in public issues. This scaffold does not claim a configured private reporting address.

A useful synthetic check is included in the contract tests: an unselected file and an uncommitted edit must not appear in generated knowledge.
